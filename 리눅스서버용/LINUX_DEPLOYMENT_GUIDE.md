# 리눅스 디플로이 서버 이미지 갤러리 설정 가이드

GitHub를 통한 배포(Deploy) 시 기존 갤러리 이미지 데이터들이 초기화되거나 엑스박스(표시 안 됨)로 나오는 현상을 먼저 해결하기 위해 적용해야 할 추가 설정 목록입니다.

## 1. 최신 코드 배포 및 디버깅 로그 확인

현재 갤러리의 이미지 업로드 경로 인식 문제가 리눅스 환경과 권한 설정의 차이로 인해 발생한 것으로 보입니다. 정확한 원인을 파악하기 위해 서버에 디버깅용 코드를 추가하여 GitHub에 올려두었습니다.

1. 리눅스 서버에서 다음 명령어를 실행하여 제가 방금 올려둔 최신 코드(디버깅 로그 포함)를 내려받아 주세요.

    ```bash
    git pull origin main
    ```

2. 프로젝트를 다시 빌드하고 서버를 재시작해 주세요.

    ```bash
    npm run build
    # 완료 후 pm2 restart <앱이름> 등 서버 재동작
    ```

3. 웹페이지에 접속하셔서 **갤러리 사진 업로드를 한 번 더 시도**해 주세요.
4. 업로드 시도 직후 서버 터미널 화면(로그)에 출력되는 `[UPLOAD DEBUG]` 또는 `[IMAGE DEBUG]` 로 시작하는 영문 에러 메시지를 복사하거나 캡처하여 저에게 전달해 주시면 즉각 오류를 수정해 드리겠습니다.

---

*(참고용 기존 설정 가이드)*
아래는 서버가 정상 작동할 때 갤러리 사진들이 GitHub 배포에 날아가지 않도록 컴퓨터 외부 폴더에 저장하게 만드는 기존 권장 가이드입니다. (위쪽의 디버깅 작업이 끝난 후 진행하셔도 무방합니다.)

## 2. 영구 저장용 외부 폴더 생성

Next.js 프로젝트 내부(`web/public/uploads`)가 아닌, 외부 경로에 사진 전용 폴더를 새롭게 만듭니다.

```bash
# 예시: /var/www/wra-data/uploads 위치에 폴더 생성 시
sudo mkdir -p /var/www/wra-data/uploads
```

## 3. 폴더 쓰기 권한 부여

리눅스 서버에서 웹사이트를 구동하는 시스템 계정이 방금 만든 폴더에 쓰기(저장) 작업을 할 수 있도록 권한을 줍니다.
*(만일 서버 실행 계정이 `ubuntu` 라면 다음과 같이 설정합니다)*

```bash
sudo chown -R ubuntu:ubuntu /var/www/wra-data/uploads
sudo chmod -R 755 /var/www/wra-data/uploads
```

## 4. 서버의 환경 변수(.env) 설정 수정

배포 중인 리눅스 서버의 `web/.env` 파일 맨 아랫줄에, 방금 생성한 폴더의 절대 경로를 `UPLOAD_DIR`로 추가해 줍니다.

```env
UPLOAD_DIR=/var/www/wra-data/uploads
```

**※ 주의사항 ※**
경로 양끝에 큰/작은따옴표 문자열(`"`, `'`)을 넣지 마시고 순수 경로값만 띄어쓰기 없이 정확히 입력해 주세요.
